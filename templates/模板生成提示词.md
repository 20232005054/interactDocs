你是一位资深临床研究方案撰写专家，同时精通 JSON 数据格式。
我需要你为"【在这里填具体试验类型】"生成一个完整的方案模板 JSON 文件。

=== 核心要求（必须严格遵守）===

**关于 generation_mode 的选择原则：**
- mode=2（直接使用）：优先选择。适用于有固定格式、标准化内容的章节。
- content_template 必须写完整的 Markdown 正文，不能只写几句话。禁止使用 LaTeX 数学公式（如 $\le$、$\ge$），直接使用 Unicode 字符（≤、≥）或文字描述（不超过、不低于）
- mode=0（复制模式）：适用于需要插入核心信息变量的章节，如 "本研究计划纳入 {{sample_size}} 例受试者"。
  content_template 中用 {{field_key}} 引用变量。
- mode=1（AI生成）：仅用于真正需要根据具体试验信息动态生成的摘要，全部模板中 mode=1 不超过 5 个。
- mode=3（AI修改）：禁止使用。

**关于 content_template 的内容要求：**
- 每个章节的 content_template 必须是完整的、专业的 Markdown 文档片段
- 最短不少于 300 字，重要章节（如研究背景、统计分析）不少于 800 字，不多于一千字
- 必须使用 Markdown 格式：
  - 用 ## 和 ### 划分小节
  - 关键数据用表格呈现（如入排标准、评估时间点、不良事件分级）
  - 列表用于枚举条目（如纳入标准、排除标准）
  - 重要术语用 **加粗**
  - 禁止使用 LaTeX 数学公式（如 $\le$、$\ge$），直接使用 Unicode 字符（≤、≥）或文字描述（不超过、不低于）
- 内容要符合 ICH E6(R2) GCP 规范和 CFDA 临床试验指导原则
- 表格示例格式：
  | 访视 | 时间窗 | 知情同意 | 体格检查 | 实验室检查 |
  |------|--------|----------|----------|------------|
  | 筛选期 | Day -14 ~ -1 | ✓ | ✓ | ✓ |

**关于 sources 的配置严格限制：**
- source.value 只能是以下三个值之一，禁止使用其他任何值：
  - "keyinfo"：引用核心信息字段（core_xxx）
  - "summary"：引用摘要字段（summary_xxx）
  - "chapter"：引用章节内容（struct_xxx）
- match_keys 必须是数组，禁止为 null
- 每个 match_key 的 value 必须是已定义的 field_key，不能是自造的字段名
- 禁止出现 source.value = "custom"、"input"、"direct" 等非标准值
- match_keys 不能为 null，如果没有匹配字段，用空数组 [] 代替，但此时整个 sources 条目也没有意义，应直接删除该 sources 条目

- mode=0 的章节，sources 中列出 content_template 里用到的所有 {{变量}}
- mode=1 的摘要，sources 列出生成时需要参考的核心信息字段
- mode=2 的章节，sources 留空数组 []

=== JSON 结构说明 ===

field_key 命名规则（全局唯一，不能重复）：
- 核心信息字段：core_xxx
- 摘要：summary_xxx  
- 章节：struct_xxx

field_type 可选值：text / select / group（group 是分组容器，没有实际值）

sources 格式（mode=0 或 mode=1 时填写）：
{
  "source": {"value": "keyinfo", "label": "关键信息", "ui_type": "select"},
  "match_type": "关键信息匹配",
  "match_keys": [{"value": "core_xxx", "label": "字段显示名"}],
  "target_field": "xxx"  // 对应 content_template 中的 {{xxx}}
}

=== 输出要求 ===

请生成包含以下内容的完整 JSON：

1. core_info_templates：
   - 3-4 个分组（group 类型），每组 3-6 个字段
   - 覆盖：试验基本信息、研究设计参数、受试者信息、给药方案

2. summary_templates：
   - 6-8 个摘要项
   - 除"研究概述"用 mode=1 外，其余全部用 mode=0
   - mode=0 的 content_template 用 {{变量}} 拼接核心信息字段

3. structure_templates：
   - 12-15 个一级章节，重要章节有 2-4 个子章节
   - 90% 的章节用 mode=2，content_template 写完整的专业内容
   - 仅"研究背景"和"讨论"可以用 mode=1
   - 必须包含：研究背景、研究目的、研究设计、受试者选择（含入排标准表格）、
     给药方案、有效性评估、安全性评估、统计分析（含样本量计算）、
     访视计划（含访视时间表格）、不良事件处理、数据管理、伦理声明

只输出 JSON，不要任何解释文字。章节结构注意划分子章节，章节题目已经有标题，内容content不需要写标题
