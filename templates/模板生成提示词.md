你是一位资深临床研究方案撰写专家，同时精通 JSON 数据格式。
我需要你为"【在这里填具体试验类型】"生成一个完整的方案模板 JSON 文件。

=== 核心要求（必须严格遵守）===

**关于 generation_mode 的选择原则：**
- mode=2（直接使用）：优先选择。适用于有固定格式、标准化内容的段落。
- content_template 必须写完整的专业正文，不能只写几句话。禁止使用 LaTeX 数学公式（如 $\le$、$\ge$），直接使用 Unicode 字符（≤、≥）或文字描述（不超过、不低于）
- mode=0（复制模式）：适用于需要插入核心信息变量的段落，如 "本研究计划纳入 {{sample_size}} 例受试者"。
  content_template 中用 {{field_key}} 引用变量，match_keys 里的 value 必须与 {{变量名}} 完全一致。
- mode=1（AI生成）：仅用于真正需要根据具体试验信息动态生成的段落，全部模板中 mode=1 不超过 5 个。
- mode=3（AI修改）：禁止使用。

**关于 content_template 的内容要求：**
- 每个段落的 content_template 必须是完整的、专业的文档片段
- 正文段落最短不少于 300 字，重要段落（如研究背景、统计分析）不少于 800 字，不多于一千字
- 内容要符合 ICH E6(R2) GCP 规范和 CFDA 临床试验指导原则
- 禁止使用 LaTeX 数学公式（如 $\le$、$\ge$），直接使用 Unicode 字符（≤、≥）或文字描述（不超过、不低于）
- 表格用 Markdown 格式：
  | 访视 | 时间窗 | 知情同意 | 体格检查 | 实验室检查 |
  |------|--------|----------|----------|------------|
  | 筛选期 | Day -14 ~ -1 | ✓ | ✓ | ✓ |

**关于 sources 的配置严格限制：**
- source.value 只能是以下三个值之一，禁止使用其他任何值：
  - "keyinfo"：引用核心信息字段（core_xxx）
  - "summary"：引用摘要字段（summary_xxx）
  - "chapter"：引用章节内容（struct_xxx）
- match_keys 必须是数组，禁止为 null
- 每个 match_key 的 value 必须是已定义的 field_key，不能是自造的字段名
- 禁止出现 source.value = "custom"、"input"、"direct" 等非标准值
- match_keys 不能为 null，如果没有匹配字段，用空数组 [] 代替，但此时整个 sources 条目也没有意义，应直接删除该 sources 条目

- mode=0 的段落，sources 中列出 content_template 里用到的所有 {{变量}}，match_keys 里的 value 必须与 {{变量名}} 完全一致
- mode=1 的段落，sources 列出生成时需要参考的核心信息字段
- mode=2 的段落，sources 留 null 或空数组

=== JSON 结构说明 ===

field_key 命名规则（全局唯一，不能重复）：
- 核心信息字段：core_xxx
- 摘要：summary_xxx  
- 章节：struct_xxx

field_type 可选值：text / number / select / group
- text：文本输入，适用于名称、描述等文字内容
- number：数值输入，适用于样本量、剂量、周期、比例等可量化参数。number 类型存储纯数字，在 content_template 中引用时需在 {{field_key}} 后手动补充单位，例如：本研究计划纳入 {{core_sample_size}} 例受试者，治疗周期为 {{core_treatment_weeks}} 周
- select：下拉选择，适用于有固定枚举值的字段（如研究阶段、给药途径）
- group：分组容器，没有实际值，用于组织子字段

para_type 可选值：paragraph（正文）/ heading1 / heading2 / heading3

sources 格式（mode=0 或 mode=1 时填写）：
{
  "source": {"value": "keyinfo", "label": "关键信息"},
  "match_type": "关键信息匹配",
  "match_keys": [{"value": "core_xxx", "label": "字段显示名"}]
}

注意：match_keys 中每个 value 即为 content_template 中对应的 {{变量名}}，两者必须完全一致。

=== 输出要求 ===

请生成包含以下内容的完整 JSON：

1. core_info_templates：
   - 3-4 个分组（group 类型），每组 3-6 个字段
   - 覆盖：试验基本信息、研究设计参数、受试者信息、给药方案
   - 样本量、剂量、治疗周期、随访时间、年龄范围等数值参数必须用 number 类型
   - 名称、描述、标准等文字内容用 text 类型
   - 研究阶段、给药途径、对照类型等枚举值用 select 类型
   - number 类型的 field_name 中注明单位，如"计划样本量（例）"、"治疗周期（周）"

2. summary_templates：
   - 6-8 个摘要项
   - 除"研究概述"用 mode=1 外，其余全部用 mode=0
   - mode=0 的 content_template 用 {{变量}} 拼接核心信息字段

3. structure_templates：
   - 12-15 个一级章节，重要章节有 2-4 个子章节
   - 每个章节通过 paragraphs 数组定义段落结构
   - 章节标题用 heading2/heading3 类型的段落（mode=2，content_template 写标题文字）
   - 正文内容用 paragraph 类型的段落
   - 90% 的正文段落用 mode=2，content_template 写完整的专业内容
   - 仅"研究背景"和"讨论"的正文段落可以用 mode=1
   - 必须包含：研究背景、研究目的、研究设计、受试者选择（含入排标准表格）、
     给药方案、有效性评估、安全性评估、统计分析（含样本量计算）、
     访视计划（含访视时间表格）、不良事件处理、数据管理、伦理声明

只输出 JSON，不要任何解释文字。
